# 房间、场景、模块验收与备份

## 房间

在 App「管理 → 房间管理」添加、改名或排序。拖动左侧手柄，或使用上移 / 下移；不再填写排序数字。「移入设备」支持一次选择最多 200 台设备，网关与模块分别选择，不改接线、设备身份或历史数据。

改名会在同一事务中更新房间、设备位置和本家庭成员的位置授权。受影响成员的旧访问令牌立即失效，客户端可通过刷新令牌取得新位置权限。全屋访问权限不改动。若成员的位置权限跨多个家庭共享，服务拒绝自动改名，避免改变另一家庭的授权。删除房间前需移出设备并调整仍引用该名称的成员权限。

## 家庭模式与一键场景

「家庭模式」决定后续自动化规则适用范围；「一键场景」立即提交设备动作。全屋场景需要管理员及全部房间权限。

新建场景时选择设备、控制项和目标值，每个设备一个动作，最多 16 台。可绑定到在家 / 离家 / 睡眠之一，每个模式只能绑定一个场景。保存不执行；切换模式时可选择是否执行绑定场景，提交前会显示动作清单供核对。

场景执行属于手动控制，相关设备自动化暂停 30 分钟。执行记录逐项等待真实设备回执，离线、超时、失败独立显示，不把入队当成完成。红外回执只说明发送成功，不说明空调实际响应；场景默认沿用设备当前红外协议与型号。部分失败不撤回其他设备已完成的动作。

客户端为一次执行保留同一执行标识，网络中断后重试不重复提交已记录的动作。已接受的场景不会因页面刷新自动重新执行。最近 20 次记录可在同一页面查看。恢复平台备份后如本地待确认记录已不存在，应先核对实际设备，再清除本地记录。

## 模块接线和功能验收

「网关模块管理 → 接线与验收」显示当前已从设备读回的模块与 GPIO。接线前断电；GPIO 编号不等于开发板排针序号。

- DHT11：按实际模块丝印连接 VCC、GND、DATA / S。裸传感器和带板模块排列不同，上拉与供电以模块说明为准。
- 声音模块：将 AO 接到所选模拟输入 GPIO，不能用 DO 代替连续采样；显示原始采样值，不标成分贝。
- 红外模块：按成品驱动模块规格接供电、共地与信号；避免 GPIO 直接驱动大功率红外灯。测试只改变电源期望值，不更改已保存的协议和型号。

ESP32 GPIO 电平需符合 [Espressif 电气规格](https://documentation.espressif.com/esp32_datasheet_en.html)，不可直接输入 5V 信号。模块额定供电与 GPIO 信号电平是不同事项，不能用 GPIO 容许电平推断模块供电方式。

传感器验收最多等待三分钟，必须收到检查开始之后的新鲜、有效采样，旧读数不能充当本次通过依据。红外测试先等待发送回执，再由使用者观察空调是否响应；人工观察仅显示在本次验收页，不伪造真实状态反馈。配置保存、传感器采样、红外发送和人工观察分别显示。

## 备份健康与恢复准备

单家庭实例的家庭所有者可在「备份与恢复」查看最近成功时间、连续失败、新鲜度、完整性校验、数据库 / Redis 恢复演练和异机副本登记。超过 36 小时无成功备份、演练或副本未完善时首页提醒；已配置通知渠道每天最多发送一次同类提醒，不自动开通外部存储或付费服务。

以下为当前部署目录。命令需在服务器 SSH 执行，App 只提供状态和可复制的指引，不接触 Docker socket，也不提供直接替换生产数据的 HTTP 接口。

```sh
cd /opt/home-guardian
# 生成备份，并在随机临时数据库及无网络 Redis 副本中演练恢复
python3 scripts/backup.py --backup-dir /root/backups/home-guardian/managed backup --keep 14 --drill
# 检查指定备份文件完整性：不等于恢复演练
python3 scripts/backup.py verify /root/backups/home-guardian/managed/<备份编号>.zip
# 单独演练指定备份；不停止或覆盖生产服务，临时数据在结束后清理
python3 scripts/backup.py --backup-dir /root/backups/home-guardian/managed drill /root/backups/home-guardian/managed/<备份编号>.zip
# 先将实际文件复制到独立机器 / 离线存储并核验，再登记；此命令本身不上传文件
python3 scripts/backup.py record-copy /root/backups/home-guardian/managed/<备份编号>.zip --label '离线硬盘 A'
```

数据库演练使用 `hg_verify_` 随机数据库，Redis 使用归档数据的私有副本并禁用网络；不挂载正在使用的 Redis 数据卷。EMQX 归档只校验文件完整性，完整服务恢复仍需在维护窗口验证，页面不会将其标为演练通过。异机副本是管理员登记的信息，系统不声称已自动核验远程内容。

实际恢复前先另存一份备份、核对版本和配置，安排维护窗口。备份来自其他代码版本时，应先准备与备份对应的应用版本；CLI 会在任何数据替换前拒绝已知的代码版本不匹配。App 根据所选备份给出完整恢复命令；恢复会替换平台数据、短暂停止服务，并自动先创建当前状态的恢复检查点。完成后重新登录，验证网页、MQTT、设备上线、遥测及待确认动作。不得把完整备份文件放到公开下载目录。

## 接口和升级

新增 `PATCH /rooms/{id}`、`PUT /rooms/order`、`PUT /rooms/{id}/devices`、`/scenes`、`/scenes/{id}/execute`、`/scene-runs` 和 `GET /devices/{id}/module-check`。原 `/rooms`、`/backups` 的 `items` 及 `/home/mode` 默认响应保持兼容；`/backups` 增加 `health`，首页概览增加只对所有者可见的 `backup_health`。只有显式 `execute_scene=true` 的模式切换返回场景运行记录。

发布需运行 `php webman migrate:run` 创建 `scenes` / `scene_runs`，不修改已有设备、模块或红外配置。迁移为事务性新增表；回退应用时可保留新表以保全运行记录，无需删除用户数据。
