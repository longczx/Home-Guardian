# ESP32 配网与联网配置

固件 1.3.0 起，长按 BOOT（默认 GPIO0）满 5 秒，会清除联网配置、重启并开启 `HG-Setup-xxxx` 热点。在连接 WiFi、平台自注册、MQTT 重试及正常运行时均可操作。检测由独立 FreeRTOS 任务每 20ms 执行，不依赖联网主循环。

## 各配置的用途与优先级

| 配置 | 用途 |
| --- | --- |
| `config.h` 硬件项 | 固件版本、BOOT 引脚、首次默认模块与引脚；已有模块清单优先 |
| `config.h` WiFi / MQTT 项 | 兼容旧的手动烧录流程，仅在未被 BOOT 重置且运行期 WiFi 为空时播种 |
| `DEFAULT_SERVER_URL` | 首次配网页的平台地址提示，示例配置默认留空；BOOT 重置后不再预填 |
| NVS `hg` | 配网页提交的 WiFi、平台地址、配对码、注册令牌和平台下发的 MQTT 凭证；日常联网读取这里 |
| NVS `hg-reset` | BOOT 重置保护标记和稳定网关 UID；重置后永久禁用编译期联网凭证播种 |
| NVS `hg-mods` / `ac_ir` | 模块清单、引脚及红外协议设置；重配网络保留这些设置 |

重置先持久化标记，再清理 `hg` 和 SDK 保存的 WiFi 参数。即使擦除时断电，下一次启动仍进入配网；失败的配网页保存不会解除标记。注册重试返回的旧凭证也不能覆盖重置。网关 UID 保留，以便后台识别原设备并使用重新配网授权。

WiFi 在后台连接；自注册失败间隔 3 秒重试，MQTT 采用退避重试。HTTP TCP/读取超时各为 2 秒，TLS 握手超时 3 秒，MQTT TCP/握手等待各为 2 秒。SDK DNS 等待另计，因此主任务看门狗设为 30 秒；BOOT 任务始终独立运行。

## 手机操作

1. 手机先连接能访问服务器的网络。在 App「添加设备」生成配对码，分别复制配对码和「当前服务器的平台地址」。切换服务器会作废本页配对码，需要重新生成。
2. 设备已有绑定时，从原网关的重新配网入口获取授权。长按 BOOT 5 秒，看到重启后连接设备的 `HG-Setup-xxxx` 热点。
3. 打开 `http://192.168.4.1/`，选择家中 2.4GHz WiFi，填写密码、配对码和平台地址并提交。两次复制可以先记在手机备忘录，断开外网后也能粘贴。
4. 手机切回原网络，回到 App 等待注册、MQTT 连接和首报。

当前服务器的平台地址示例：`http://107.149.87.86`。不要加 `/app/`、`/api` 或 MQTT 的 `:1883`；如服务器使用自定义 HTTP(S) 端口，需要保留该端口。配网页用平台地址请求 `/api/provisioning/register`，MQTT 主机和端口由平台响应下发，无需在配网页填写。

完整擦除芯片 Flash 会同时删掉重置保护标记和模块配置；普通固件升级只写应用分区即可保留这些数据。升级后必须在实机验证：错误 WiFi、不可达平台、MQTT 不响应三种情况下长按 BOOT，均应出现重置日志并重启进入热点，再断电重启仍保持待配网。
