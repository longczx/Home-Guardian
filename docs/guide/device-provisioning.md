# ESP32 配网与联网配置

固件 1.3.0 起，长按 BOOT（默认 GPIO0）满 5 秒，会清除联网配置、重启并开启 `HG-Setup-xxxx` 热点。在连接 WiFi、平台自注册、MQTT 重试及正常运行时均可操作。检测由独立 FreeRTOS 任务每 20ms 执行，不依赖联网主循环。

仓库默认使用 App 配对码配网：WiFi 名称/密码、平台地址、MQTT 主机/密码和固定网关 UID 均为空。`MQTT_PORT=1883` 仅是标准默认端口，实际 MQTT 主机、端口和凭证在配网注册后由平台返回。

`firmware/include/config.h` 是被 Git 忽略的本地配置，`git pull` 不会更新已有文件。已有配置可在仓库根目录执行以下命令，只同步联网默认值和固件版本，保留其他内容，包括模块启用开关、GPIO 引脚、模块 UID 及红外协议：

```bash
python3 scripts/configure-app-provisioning.py
```

没有本地配置时，先复制 `firmware/include/config.example.h` 为 `firmware/include/config.h`。清理编译期默认值不会删除板上已保存的联网配置；若要重新配网，烧录后长按 BOOT 5 秒。

## App 动态模块管理（固件 1.4.0 起）

在 App「设备管理 → 编辑网关 → 模块管理」中读取网关实际模块清单，再添加模块、修改 GPIO 或移除模块。支持 DHT11、声音传感器和一路红外空调，最多 8 个模块。页面等待设备执行回执，再次读取设备清单核对，确认一致后才显示成功；失败或超时请先刷新核对，不要连续重复提交。

引脚选项由固件返回，App 与固件均检查引脚占用。针对当前 `esp32dev` 板型，禁止新配置使用 Flash、UART0、启动绑带、BOOT 及未引出的引脚；检测到 PSRAM 时额外保留 GPIO16/17。声音模块限 ADC1 可用引脚，DHT11 和红外必须使用支持输出的引脚。引脚限制依据 [Espressif ESP32 GPIO 文档](https://docs.espressif.com/projects/esp-idf/en/v4.4.7/esp32/api-reference/peripherals/gpio.html)。已有配置不会因为新限制而自动改写；需要调整时选择设备提供的可用引脚。

修改 GPIO 保留原模块 UID、名称和历史设备关系；红外协议、型号、当前控制状态及上次发送状态也保留。先断电调整接线，上电后在 App 保存新引脚。新驱动初始化成功且 NVS 保存成功后才替换旧驱动，失败保留原配置。配置应用成功不代表传感器接线正常或空调实际收到红外，请继续验证读数和控制效果。

示例配置首次默认不挂载模块，上线后从 App 添加。旧设备已有 NVS 清单优先，升级不覆盖；旧 `config.h` 中开启的默认模块仅在清单从未保存时播种。主动删除全部模块会保存空清单，断电重启仍为空。损坏的存储数据会保留并提示错误，不自动恢复默认模块。

旧固件可尝试读取已有清单，但新版管理功能需要自行编译刷入 1.4.0 或更新版本；只更新 App 不会升级 ESP32。BOOT 5 秒只重置联网配置，不清除模块或红外协议。

## 各配置的用途与优先级

| 配置 | 用途 |
| --- | --- |
| `config.h` 硬件项 | 固件版本、BOOT 引脚、首次默认模块与引脚；已有模块清单优先 |
| `config.h` WiFi / MQTT 项 | 兼容旧的手动烧录流程，仅在未被 BOOT 重置且运行期 WiFi 为空时播种 |
| `DEFAULT_SERVER_URL` | 首次配网页的平台地址提示，示例配置默认留空；BOOT 重置后不再预填 |
| NVS `hg` | 配网页提交的 WiFi、平台地址、配对码、注册令牌和平台下发的 MQTT 凭证；日常联网读取这里 |
| NVS `hg-reset` | BOOT 重置保护标记和稳定网关 UID；重置后永久禁用编译期联网凭证播种 |
| NVS `hg-mods` / `ac_ir` | 模块清单、引脚及红外协议设置；重配网络保留这些设置 |

重置先持久化标记，再清理 `hg` 和 SDK 保存的 WiFi 参数。即使擦除时断电，下一次启动仍进入配网；失败的配网页保存不会解除标记。注册重试返回的旧凭证也不能覆盖重置。网关 UID 保留，以便后台识别原设备并使用重新配网授权。

WiFi 在后台连接；自注册失败间隔 3 秒重试，MQTT 采用退避重试。HTTP TCP/读取超时各为 2 秒，TLS 握手超时 3 秒，MQTT TCP/握手等待各为 2 秒。SDK DNS 等待另计，因此主任务看门狗设为 30 秒；BOOT 任务始终独立运行。

## 手机操作

1. 手机先连接能访问服务器的网络。在 App「添加设备」生成配对码，分别复制配对码和「当前服务器的平台地址」。切换服务器会作废本页配对码，需要重新生成。
2. 设备已有绑定时，从原网关的重新配网入口获取授权。长按 BOOT 5 秒，看到重启后连接设备的 `HG-Setup-xxxx` 热点。
3. 打开 `http://192.168.4.1/`，选择家中 2.4GHz WiFi，填写密码、配对码和平台地址并提交。两次复制可以先记在手机备忘录，断开外网后也能粘贴。
4. 手机切回原网络，回到 App 等待注册、MQTT 连接和首报。

当前服务器的平台地址示例：`http://107.149.87.86`。不要加 `/app/`、`/api` 或 MQTT 的 `:1883`；如服务器使用自定义 HTTP(S) 端口，需要保留该端口。配网页用平台地址请求 `/api/provisioning/register`，MQTT 主机和端口由平台响应下发，无需在配网页填写。

完整擦除芯片 Flash 会同时删掉重置保护标记和模块配置；普通固件升级只写应用分区即可保留这些数据。升级后必须在实机验证：错误 WiFi、不可达平台、MQTT 不响应三种情况下长按 BOOT，均应出现重置日志并重启进入热点，再断电重启仍保持待配网。
