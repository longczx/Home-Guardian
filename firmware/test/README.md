# 红外自检工具（排查空调"完全没反应"）

两个独立 Arduino sketch，用来把问题**分层定位**：到底是发射管坏/没接好、引脚不对，还是协议不对。

> 用 **Arduino IDE** 最省事：库管理器搜 `IRremoteESP8266` 安装 → 打开对应 `.ino` →
> 改顶部引脚常量 → 选好 ESP32 开发板 → 上传 → 打开串口监视器（115200）。
> （PlatformIO 主工程只编 `src/`，这些测试稿不参与主构建。）

## 排查顺序

### 第 1 步：发射管到底发不发？ → `ir_send_test`

烧录 `ir_send_test/ir_send_test.ino`（改 `kIrLedPin` 为你接发射管的 GPIO）。

**用手机摄像头对准红外发射管**——发射瞬间应看到**淡紫色/白色闪烁**（红外人眼不可见，但手机能拍到，前置摄像头通常更灵敏）。

| 现象 | 结论 |
|---|---|
| 看到闪烁 | 发射管 + 接线 + 引脚都正常 → 跳到第 3 步 |
| **没有任何闪烁** | 硬件问题：见下面「发射不亮的排查」 |

#### 发射不亮的排查
1. **引脚是否可输出**：ESP32 的 `GPIO34/35/36/39` 是**只输入**引脚，接发射管永远没输出——这是最常见的坑。换 `GPIO25/26/27/4/17` 之类。
2. **发射管极性**：长脚(+)、短脚(-)；接反不亮。
3. **驱动**：裸发射管直连 GPIO 电流不足、射程仅几厘米甚至看不出；正确接法是经三极管驱动（见 `docs/guide/ac-ir-control.md`）。做自检时可先直连看有没有微弱闪烁，确认通路。
4. **接触**：面包板/杜邦线虚接。

### 第 2 步：接收头正常吗？（可选，用来确认发射）→ `ir_receive_test`

烧录 `ir_receive_test/ir_receive_test.ino`（改 `kRecvPin`）。把跑着第 1 步的**发射板对准接收头**，串口应持续打印收到 `NEC 0xFFE01F`。收到即证明发射管确实在发。

### 第 3 步：认出你海信空调的协议 → `ir_receive_test`

还是这个接收自检：**对着接收头按海信空调的实体遥控**，看串口的 `Protocol:` 行，例如：

```
Protocol : COOLIX
```

这个名字就是你要的协议。两种用法：
- 填进 `firmware/include/config.h` 的 `AC_PROTOCOL`（首次默认值），或
- 直接在 App 空调详情页的「红外协议」选择器里选同名项（运行时切换，推荐）。

## 回到主固件仍不通？

确认这些（主固件 `firmware/`，非本测试稿）：
1. `config.h` 里 `AC_IR_ENABLED` = `1`，且 `IR_LED_PIN` 与你实际接线一致（可输出引脚）。
2. App 里点空调开关时，**串口是否打印 `[CMD] 收到指令: action=set_state`**：
   - 有打印 → 指令到位，问题在红外硬件/协议（回第 1、3 步）。
   - 没打印 → 问题在上游：设备没套「空调」能力模板、或 `set_state` 未注册、或 MQTT 没连上。
3. 协议对但空调不理：**发射管正对室内机接收窗、靠近些**（红外要基本对准，隔墙/大角度会失败）。
